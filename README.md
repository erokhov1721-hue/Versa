# Versa

Сравнение коммерческих предложений подрядчиков на тендерах в строительстве.

## Установка

```bash
pip install -e ".[dev]"
```

## Запуск интерфейса

```bash
streamlit run versa/ui/app.py
```

Загрузите файл сводной таблицы (.xlsx, лист «3\_ ПОДРОБНАЯ»).

Интерфейс — две вкладки:
- **«Сводная по смете»** (открывается первой) — вся смета в исходном порядке строк,
  колонка на каждого участника, подсветка минимума/максимума по каждой строке,
  колонка «Лучшее предложение», строки ИТОГО/НДС. В сайдбаре — уровень детализации
  (Разделы / Подразделы / Все позиции), галочка «Скрыть незаполненные разделы»,
  единицы (руб. / тыс. руб. / млн руб.), ставка НДС и раскрытие отдельных разделов
  независимо от общего уровня детализации.
- **«Аналитика»** — прежний экран этапа 1: сводка итогов, таблица по разделам,
  водопады, тепловая карта отклонений, предупреждения.

## Запуск в Docker

```bash
docker build -t versa:latest .
docker run -d --name versa --restart unless-stopped -p 8501:8501 versa:latest
```

Приложение будет на порту 8501 (порт можно поменять флагом `-p` и опцией
`--server.port` в Dockerfile). `samples/` и `docs/` в образ не попадают
(см. `.dockerignore`) — в них тестовые данные тендера и рабочие планы,
им незачем лежать на боевом сервере.

## Тесты

```bash
pytest -v
```

## Что показалось странным/неоднозначным в образце

- У «Р.И.К. ИНЖИНИРИНГ» формула «Стоимость всего за объёмы заказчика» (`AQ`)
  сломана почти на всех строках (`#DIV/0!`, ~385 из 1650) — судя по всему,
  это протянутая вниз формула `=AD*AL` вместо `=H*AL`. Мы её не читаем и
  всегда пересчитываем сами.
- Кроме заявленных разделов 6 («Фасадные работы») и 10 («ВИС»), в файле
  нашёлся ещё и третий раздел с реальными ценами: строки 1603–1607,
  номер в столбце B — «18», а название в столбце C — «16. Разработка
  рабочей документации», суммы там в десятках-сотнях миллионов рублей.
  Наше правило «скрывать разделы без единой цены» не делает исключений по
  названию, поэтому этот раздел сейчас тоже показывается в сравнении —
  возможно, для инструмента сравнения именно фасадов и ВИС его стоит
  скрывать отдельным правилом, но на этом этапе мы ничего не прячем молча.
- «99 позиций у ГЭС по 0,01 ₽» — это только часть картины. Из этих 99
  ячеек 80 на самом деле сопровождаются комментарием «включено в п/п NNN»
  (то есть это `included_elsewhere`, а не просто заглушка), ещё 17 — «не
  включено...» (`not_included`), и только 2 — самостоятельная заглушка без
  ссылки («Задвоение с позициями ..»). Статус определяется по совокупности
  цены и комментария, а не по одному правилу «цена < 1 ₽».
- Комментарии написаны свободным текстом с опечатками («Вклучено», а также
  «не Вклучено» — отрицание той же опечатки), без единого словаря
  формулировок. Список подстрок в `status.py` — не исчерпывающий, на новых
  тендерах его почти наверняка придётся расширять.
- Ссылки «включено в п/п NNN» иногда содержат несколько номеров через
  запятую с непоследовательными пробелами («856, 858, 860 ,862»).
- Нумерация раздела в столбце B и его название в столбце C иногда расходятся
  (раздел с номером 6.8 назван «6.10. ...», а «18» назван «16. ...») —
  судя по всему, разделы переносили/перенумеровывали, а текст не обновили.
- Шаблон рассчитан на весь объект целиком (разделы 1–10+), но в конкретном
  тендере заполнены только «Фасадные работы», часть «Инженерных систем» и
  «Разработка рабочей документации» — то есть один и тот же файл может
  представлять очень разную долю проекта в разных тендерах, и «итог по всем
  разделам» не значит «итог по всему зданию».
- В самом конце листа (после раздела 18) есть отдельный блок анкетных вопросов
  («Аванс», «Гарантия на работы», «СРО и лимит ответственности»...) — колонка B
  там просто текст, а не номер раздела, и колонка A заново начинается с 1. Это не
  часть сметы, и парсер теперь явно проверяет, что номер раздела — это цифры с
  точками, а не любой текст, иначе эти 26 строк превратились бы в фиктивные разделы.
- **Раздел 18 «Рабочая документация» участвует во всех итогах** («Сводная по смете»,
  ИТОГО, «Лучших предложений по разделам») — при разработке этого экрана выяснилось,
  что без него ИТОГО и подсчёт побед по разделам получаются другими: с разделом 18
  минимум/максимум по ИТОГО — ПАРАЛЛЕЛЬ (~2781,9 млн ₽) и ФОДД (~4489,3 млн ₽), а
  «лучших по разделам» — трое (ПАРАЛЛЕЛЬ, Р.И.К., ЭРБЕК) вместо двух. Победа ЭРБЕК в
  разделе 18 обманчива: они оценили только 2 из 5 позиций там, остальные — «не
  включено», из-за чего их сумма формально мизерная (4 500 ₽ против 29–207 млн ₽ у
  остальных).
- **Разница между «за объёмы участника» и «за объёмы заказчика»** обычно не больше
  копейки (заглушки по 0,01 ₽ на нулевом объёме заказчика), но у **ГЭС и ЭРБЕК** она
  настоящая: ≈168,4 млн ₽ и ≈92,7 млн ₽ соответственно. Причина — одна и та же строка
  1603 «Рабочая документация, корректировка»: у заказчика объём «1», а эти двое
  посчитали цену на объём «20606,16». Это уже отмечено предупреждением о расхождении
  объёмов, отдельно ничего не меняли.
